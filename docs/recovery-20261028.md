- 恢复可中断 TCP/ping/HTTP、HTTP 重连和有界资源释放，成套恢复流量时序及 UDP 响应大小。
- 修正 QoS 更新顺序；无会话 ID 且多 PDU 复用同一 QFI 时不猜归属，返回关联不完整。
- 恢复按容器 ID/启动时间失效的会话日志缓存；有界保留原生事件、重叠去重，拒绝跨重启使用历史证据。
- 从 nrMAC_stats.log 读取真实 RAN 指标并检查字段完整性；保留 Git 较新的数据库投影和检查点。
- 使用独立主机 profile 固定镜像与 CPU 集合。gNB 按容器 init 的直接子进程识别主进程，线程就绪后精确绑定协议/射频池并读回，不按名称批量操作其他进程。

OAI 的 MAC/DCI/DRB 源码修复材料在 patches/oai，绑定恢复证据；本轮使用保留且固定的已验收 OAI 镜像，没有重建完整 OAI 编译树，也不声称证明历史无线故障唯一根因。

## 操作入口

Python 为 `.venv/bin/python`，其基座位于 `../.runtime/python`。参考依赖在 `../.dependencies`，OAI 标签 2026.w35、free5gc-compose 标签 v4.1.0。OAI 参考为稀疏源码引用，不能视作完整构建目录。

以下准备命令要求当前没有运行中的仿真。构建基于现存完整镜像，不依赖旧 Windows 代理。

```bash
cd /home/xzy/MergedSystem/TestBed
bash scripts/operations/build_recovery_images.sh
.venv/bin/python scripts/operations/prepare_ibn3090.py \
  --run-id merged-recovery-protocols-20261028-1 --protocols --activate-run
bash with-testbed.sh .venv/bin/python -m testbed.cli host-check \
  --scenario scenarios/validation/ibn3090-protocols.yaml
bash with-testbed.sh .venv/bin/python -m testbed.cli start \
  scenarios/validation/ibn3090-protocols.yaml --run-id merged-recovery-protocols-20261028-1
bash with-testbed.sh .venv/bin/python scripts/operations/verify_recovery.py
```

同一个已存在的 run 使用 `resume --run-id ...` 或 `status --run-id ...`；不要重复 start 或重建原始证据。停止使用 `stop --run-id ...`，保留状态、日志和卷。代码/镜像修订只能在当前任务退出并恢复、停止后执行，`record_recovery_revision.py` 会保存旧 profile 和逐文件源码哈希。
